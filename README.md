# FabPulse — MES → ERP → SCM Command Center

A high-fidelity semiconductor fab command center that integrates Manufacturing Execution (MES), Enterprise Resource Planning (ERP), and Supply Chain Management (SCM) in a single dark-theme interface. Pure front-end — no backend, no database, no network requests. All data is generated by a seeded deterministic simulation running on a 180-second loop.

## What it is

FabPulse demonstrates an end-to-end operational story: purchase order → goods receipt → production lot → completed wafers → outbound shipment → delivery. Twenty-one operational modules span three domains, each updating live as the simulation clock advances.

| Domain | Modules | Description |
|--------|---------|-------------|
| **MES** | 7 | Fab Floor, Production WIP, Equipment E10, SPC/Quality, Recipe Mgmt, Alarms, KPI Dashboard |
| **ERP** | 10 | Document Flow, MRP/Planning, Sales Orders, Production Orders, Finance, Inventory, Procurement, Materials, Business Partners, Bill of Materials |
| **SCM** | 4 | Control Tower, Shipments, Demand Planning, Supplier Scorecards |

A **Handbook** page (Help > Guidance) provides bilingual (繁中/EN) reference docs for every module and four system topics.

## Quick start

```bash
npm install
npm run dev          # Vite dev server at http://localhost:5173
npm run build        # Production build
npm run preview      # Serve the production build locally
```

> **Windows/WSL note:** node_modules are installed under WSL. Use `node node_modules/vite/bin/vite.js` if the `npm run` shims don't resolve. See the [Windows build/run memory note](https://claude.ai) for details.

## Testing

```bash
node node_modules/vitest/vitest.mjs run      # run all tests once
node node_modules/vitest/vitest.mjs          # watch mode
```

Global vitest environment is **node** (pure-logic: PRNG, event bus, KPI/SPC math, ERP generators). Component tests opt into jsdom with the per-file pragma on line 1:

```ts
// @vitest-environment jsdom
```

Component test files use the `*.dom.test.tsx` suffix. See [CLAUDE.md](CLAUDE.md) for the full testing setup.

## Guided tour & Handbook

New visitors see a one-time welcome prompt to start the guided tour. The tour is bilingual (繁中/EN), 42 steps across 5 chapters, and auto-navigates the app — it switches pages, spotlights panels, opens drill-in details, and waits for live simulation events to fire.

Open the **Tour Center** (`?` button or `?` key) to browse four tours (full flow + MES/ERP/SCM chapters) with estimated times and completion tracking.

The **Handbook** (`Help > Handbook` in the sidebar) is a searchable bilingual reference for every module and system topic, with "Open page" and "Tour this page" deep links.

## Architecture

- **Single clock** (`src/lib/clock.ts`): 180-second deterministic loop. `loopT()` = position within the loop. `loopIndex()` = monotonic loop counter.
- **Event bus** (`src/lib/eventBus.ts`): RxJS Subject with a 1000-event ring buffer. MES, ERP, and SCM engines all publish to the same bus.
- **Three simulation engines** + bridge + shipment driver, all seeded from separate PRNG namespaces (seed 0, 1000, 2000) so domains are independent but deterministic.
- **All modules React.lazy-loaded** with per-route `ErrorBoundary` and `Suspense` fallback skeletons.
